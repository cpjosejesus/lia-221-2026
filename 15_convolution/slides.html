Convolution on the GPU

You already know what a convolution computes. This session is about how to compute it fast on a GPU: mapping threads to outputs, ghost cells and divergence, the arithmetic intensity of each kernel, constant memory and the cache hierarchy, and tiling when input tiles are larger than output tiles.

Based on chapter 7 of Programming Massively Parallel Processors (Hwu, Kirk, El Hajj). Runnable code for every kernel: ec2/05_conv (laptop or Google Colab). Navigate with → ← or space; press p to print.

Why convolution is a good GPU problem, and a tricky one

  • Every output element is computed independently: ideal data parallelism, one thread per output.
  • Many operations per output: (2r + 1)² multiply-adds in 2D, so large images mean huge amounts of work.
  • But neighbouring outputs share most of their inputs: the same input element is read by up to (2r + 1)² threads.
  • And the edges need boundary handling (ghost cells), in 2D on four sides.
  • Sharing plus awkward boundaries make convolution the classic case for sophisticated tiling and data staging.

Threads to output elements

16 × 16 image, 4 × 4 blocks of 4 × 4 threads, 5 × 5 filter (r = 2)

Code: the basic 2D kernel

__global__ void convolution_2D_basic_kernel(
    const float* N, const float* F, float* P,
    int r, int width, int height) {
  int outCol = blockIdx.x * blockDim.x + threadIdx.x;
  int outRow = blockIdx.y * blockDim.y + threadIdx.y;
  if (outRow < height && outCol < width) {
    float Pvalue = 0.0f;                 // in a register
    for (int fRow = 0; fRow < 2*r + 1; ++fRow)
      for (int fCol = 0; fCol < 2*r + 1; ++fCol) {
        int inRow = outRow - r + fRow;
        int inCol = outCol - r + fCol;
        if (inRow >= 0 && inRow < height &&
            inCol >= 0 && inCol < width)   // skip ghost cells
          Pvalue += F[fRow*(2*r + 1) + fCol]
                  * N[inRow*width + inCol];
      }
    P[outRow*width + outCol] = Pvalue;
  }
}
  • Same thread mapping as the grayscale kernel: a 2D grid, typically 32 × 32 threads per block.
  • The patch of each output starts at (outRow − r, outCol − r); the double loop walks the filter.
  • Ghost cells count as 0, so the test simply skips them.
  • Pvalue accumulates in a register and is written once at the end.
  • The outer if handles images whose size is not a multiple of the block.
  • Linearized indices: N, F and P are dynamically allocated 1D arrays.

Ghost cells cause divergence, but only at the edges

width
height
filter radius r
  • Threads near an edge skip a different number of filter positions, so threads of the same warp take different paths in the inner if: control divergence.
  • Its cost grows with the filter radius and shrinks with the image size. For real images and small filters it is minor.
  • The bigger problem is memory bandwidth (next slide).

Arithmetic intensity: the real bottleneck

Ideal: an n × n image, n² outputs × m² multiply-adds = 2n²m² FLOP; reading the input and writing the output once = 8n² B (the filter is negligible) → m²/4 FLOP/B. A 3 × 3 filter (2.25) can never be compute-bound on an H100; an 11 × 11 one (30.25) can. The basic kernel loads 8 B (one N, one F) for every 2 FLOP: 0.25, whatever the filter.

The filter belongs in constant memory

toy warp of 8 threads computing 8 consecutive outputs of one row

Three properties of F: it is small (radius 7 or less in most applications; even in 3D at most 7³ = 343 elements), it does not change while the kernel runs, and all threads read it, in the same order. Constant memory is limited to 64 KB, which F easily fits.

Code: declaring, filling and using constant memory

#define FILTER_RADIUS 2
// global scope, outside any function
__constant__ float F_c[2*FILTER_RADIUS + 1][2*FILTER_RADIUS + 1];

// host: copy the filter once, before the launches
cudaMemcpyToSymbol(F_c, F_h,
    (2*FILTER_RADIUS + 1) * (2*FILTER_RADIUS + 1) * sizeof(float));

__global__ void convolution_2D_const_mem_kernel(
    const float* N, float* P, int width, int height) {
  int outCol = blockIdx.x * blockDim.x + threadIdx.x;
  int outRow = blockIdx.y * blockDim.y + threadIdx.y;
  if (outRow >= height || outCol >= width) return;
  float Pvalue = 0.0f;
  for (int fRow = 0; fRow < 2*FILTER_RADIUS + 1; ++fRow)
    for (int fCol = 0; fCol < 2*FILTER_RADIUS + 1; ++fCol) {
      int inRow = outRow - FILTER_RADIUS + fRow;
      int inCol = outCol - FILTER_RADIUS + fCol;
      if (inRow >= 0 && inRow < height && inCol >= 0 && inCol < width)
        Pvalue += F_c[fRow][fCol] * N[inRow*width + inCol];
    }
  P[outRow*width + outCol] = Pvalue;
}
  • __constant__ must be at file scope. Kernels use it as a global variable: no pointer parameter for F.
  • cudaMemcpyToSymbol(dest, src, bytes) also tells the runtime the data will not change during kernel execution.
  • Only N comes from global memory now: 2 FLOP per 4 B = 0.5 FLOP/B, twice the basic kernel.
  • Normal C++ scoping applies: if host and kernel code are in different files, the kernel file needs an extern declaration of F_c.
  • Alternative: put the weights in a struct and pass it by value. Kernel parameters live in constant memory too, and the runtime copies them at each launch, so different launches can use different filters.

Input tiles are larger than output tiles

output tile t
filter radius r
  • Output tile: the outputs one block computes. Input tile: every input element needed for them.
  • The input tile extends r elements beyond the output tile on every side: the halo.
  • A 4 × 4 output tile with a 5 × 5 filter needs an 8 × 8 input tile, 4 times larger. Real tiles are bigger: 16 × 16 → 20 × 20 = 400 elements, still about 1.6 times.
  • Unlike the matrix product of session 13, the tiles differ in size, which is what complicates the kernel.

The tiled kernel, step by step

FILTER_RADIUS = 1, IN_TILE_DIM = 8, OUT_TILE_DIM = 6

Code: tiled kernel with the halo in shared memory

#define IN_TILE_DIM 32
#define OUT_TILE_DIM (IN_TILE_DIM - 2*FILTER_RADIUS)
__constant__ float F_c[2*FILTER_RADIUS+1][2*FILTER_RADIUS+1];

__global__ void convolution_tiled_2D_const_mem_kernel(
    const float* N, float* P, int width, int height) {
  int col = blockIdx.x*OUT_TILE_DIM + threadIdx.x - FILTER_RADIUS;
  int row = blockIdx.y*OUT_TILE_DIM + threadIdx.y - FILTER_RADIUS;
  // phase 1: every thread loads one element of the input tile
  __shared__ float N_s[IN_TILE_DIM][IN_TILE_DIM];
  if (row >= 0 && row < height && col >= 0 && col < width)
    N_s[threadIdx.y][threadIdx.x] = N[row*width + col];
  else
    N_s[threadIdx.y][threadIdx.x] = 0.0f;   // ghost cell
  __syncthreads();
  // phase 2: only the inner threads compute an output element
  int tileCol = threadIdx.x - FILTER_RADIUS;
  int tileRow = threadIdx.y - FILTER_RADIUS;
  if (col >= 0 && col < width && row >= 0 && row < height &&
      tileCol >= 0 && tileCol < OUT_TILE_DIM &&
      tileRow >= 0 && tileRow < OUT_TILE_DIM) {
    float Pvalue = 0.0f;
    for (int fRow = 0; fRow < 2*FILTER_RADIUS + 1; ++fRow)
      for (int fCol = 0; fCol < 2*FILTER_RADIUS + 1; ++fCol)
        Pvalue += F_c[fRow][fCol] * N_s[tileRow + fRow][tileCol + fCol];
    P[row*width + col] = Pvalue;
  }
}
// launch: dim3 block(IN_TILE_DIM, IN_TILE_DIM),
//         grid(cdiv(width, OUT_TILE_DIM), cdiv(height, OUT_TILE_DIM))
  • Blocks are spaced OUT_TILE_DIM apart but are IN_TILE_DIM wide: neighbouring blocks overlap by 2r, each loading its own copy of the halo.
  • Ghost cells are stored as 0, so phase 2 needs no boundary test on the filter loop.
  • One barrier: the read-after-write dependence between loading and using the tile. There is no second phase, so no write-after-read barrier.
  • The thread at (tx, ty) computes output (tx − r, ty − r) of the tile from the patch starting at N_s[ty − r][tx − r].

How much did tiling buy?

ridge (FLOP/B)
  • Internal block: t² outputs × m² multiply-adds = 2t²m² FLOP. It loads (t + m − 1)² inputs and stores t² outputs, 4 B each.
  • Intensity = 2t²m² / (4((t + m − 1)² + t²)): it approaches the ideal m²/4 as t grows, because a larger output tile reuses each loaded element more.
  • Example: 5 × 5 filter, 32 × 32 blocks → 28 × 28 output tiles: 5.42 FLOP/B, close to the ideal 6.25 and 21 times the basic kernel.
  • Small filters stay memory-bound however large the tile. Large filters with large tiles become compute-bound.
  • t is capped by the 1024 threads per block and by shared memory; later chapters show ways around both.
  • Blocks at the image edge load fewer elements (ghost cells are not loaded); for large images that effect is negligible.

The cost of block = input tile

IN_TILE_DIM
FILTER_RADIUS
image width
  • Idle threads: the outer ring only loads. Fine for a memory-bound kernel (more loads in flight), wasteful for a compute-bound one.
  • Odd tile widths: 32 − 2r is not a power of two, so each block's output rows start at unaligned addresses and stores are less efficient.
  • Large filters shrink the output tile: the input tile cannot grow past 32 × 32, so bigger r means smaller t, lower intensity and both problems above made worse.
  • Fixes: make the block the size of the output tile and let threads loop to load the input tile, or do not put the halo in shared memory at all (next slide).

Leaving the halo to the caches

toy tiles of 6 × 6, 3 × 3 filter

The halo of one tile is the interior of its neighbours. By the time a block needs it, the neighbour has very probably loaded it, so it is waiting in L2 and costs no extra DRAM traffic.

Code: tiled kernel with cached halos

#define TILE_DIM 32
__global__ void convolution_cached_tiled_2D_const_mem_kernel(
    const float* N, float* P, int width, int height) {
  int col = blockIdx.x*TILE_DIM + threadIdx.x;
  int row = blockIdx.y*TILE_DIM + threadIdx.y;
  __shared__ float N_s[TILE_DIM][TILE_DIM];      // tile only
  if (row < height && col < width)
    N_s[threadIdx.y][threadIdx.x] = N[row*width + col];
  else
    N_s[threadIdx.y][threadIdx.x] = 0.0f;
  __syncthreads();
  if (col < width && row < height) {
    float Pvalue = 0.0f;
    for (int fRow = 0; fRow < 2*FILTER_RADIUS + 1; ++fRow)
      for (int fCol = 0; fCol < 2*FILTER_RADIUS + 1; ++fCol) {
        int sx = threadIdx.x - FILTER_RADIUS + fCol;
        int sy = threadIdx.y - FILTER_RADIUS + fRow;
        if (sx >= 0 && sx < TILE_DIM && sy >= 0 && sy < TILE_DIM) {
          Pvalue += F_c[fRow][fCol] * N_s[sy][sx];        // inside the tile
        } else {
          int gy = row - FILTER_RADIUS + fRow, gx = col - FILTER_RADIUS + fCol;
          if (gy >= 0 && gy < height && gx >= 0 && gx < width)
            Pvalue += F_c[fRow][fCol] * N[gy*width + gx];  // halo: L2
        }                                                   // else: ghost
      }
    P[row*width + col] = Pvalue;
  }
}
  • Input tile, output tile and block are all TILE_DIM × TILE_DIM: loading is one element per thread, and nobody is idle.
  • The loading condition is simpler: no halo, so only the usual "inside the image" test.
  • The compute loop is more complex: each patch element is either in the tile (shared memory), in the halo (global memory, usually an L2 hit) or a ghost cell (skipped).
  • Power-of-two tiles also mean aligned stores and less memory and control divergence than the previous kernel.

Summary

  • One thread per output element, a 2D grid of 2D blocks; ghost cells are skipped, causing divergence only near the edges.
  • The basic kernel reaches 0.25 FLOP/B, far from the ideal m²/4: convolution kernels are limited by memory bandwidth unless they reuse data on chip.
  • Constant memory fits the filter: small, read-only during the kernel, read in the same order by all threads. The constant cache broadcasts it and removes all DRAM traffic for F (0.5 FLOP/B).
  • Tiling: blocks load an input tile, larger than their output tile by the halo, into shared memory and reuse it. Intensity approaches m²/4 as tiles grow.
  • Block = input tile is simple to load but leaves threads idle and tiles of odd width; caching the halo in L2 keeps tiles, blocks and outputs the same power-of-two size.
