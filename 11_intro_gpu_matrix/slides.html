Intro to the GPU: grids, images and matrices

Session 10 cut a picture into ten strips for ten CPU cores. A GPU gives every pixel its own thread. This session is about how those threads are organised, how each one finds its data, and three kernels built on that: grayscale, blur and matrix multiplication.

The thread hierarchy: grid → blocks → threads

dim3: describing the grid and the blocks

__global__ void vecAddKernel(const float* A, const float* B, float* C, int n) {
  int i = blockIdx.x * blockDim.x + threadIdx.x;
  if (i < n) C[i] = A[i] + B[i];
}

void vecAdd(const float* A_d, const float* B_d, float* C_d, int n) {
  dim3 block(256);                     // y and z default to 1
  dim3 grid((n + 255) / 256);          // enough blocks to cover n
  vecAddKernel<<<grid, block>>>(A_d, B_d, C_d, n);
}
  • dim3 holds three sizes. Unused ones default to 1: dim3 block(256) is 256 × 1 × 1.
  • First launch parameter: the grid, in blocks. Second: each block, in threads.
  • In the kernel, the sizes are the built-ins gridDim and blockDim; positions are blockIdx and threadIdx.
  • 1D shorthand: kernel<<<(n + 255) / 256, 256>>>(…).
  • The grid follows the data: n = 1000 gives 4 blocks, n = 4000 gives 16.

    void toGray(unsigned char* gray_d, const unsigned char* rgb_d, int width, int height) {

// inside the kernel, every thread computes
int col = blockIdx.x * blockDim.x + threadIdx.x;
int row = blockIdx.y * blockDim.y + threadIdx.y;
if (col < width && row < height) { /* this pixel exists */ }
    • x is the horizontal direction, columns; y is vertical, rows.
    • Blocks of 16 × 16 = 256 threads, a multiple of 32 as the hardware prefers.
    • Grid sized by rounding up: (width + 15) / 16 is ceil(width / 16.0) in integers.
    • A 1920 × 1080 frame: 120 × 68 = 8160 blocks, 2 088 960 threads for 2 073 600 pixels.
    • The guard stops the extra threads: 1080 is not a multiple of 16, so the last row of blocks has 8 working rows out of 16.

    Memory is flat: row-major order

    Flattening by hand

    // 2D: row j, column i, width elements per row
M[j][i]            →  M[j * width + i]

// 3D: plane z of height rows of width elements
P[z][y][x]         →  P[(z * height + y) * width + x]
int plane = blockIdx.z * blockDim.z + threadIdx.z;
int row   = blockIdx.y * blockDim.y + threadIdx.y;
int col   = blockIdx.x * blockDim.x + threadIdx.x;
if (plane < depth && row < height && col < width)
  P[(plane * height + row) * width + col] = …;
    • A 2D array is stored as one long line, row after row.
    • For arrays with sizes known at compile time, M[j][i] works: the compiler does this arithmetic.
    • A picture loaded at run time has a size known only at run time, so you flatten it yourself.
    • j * width skips the rows before row j; + i moves along the row.
    • 3D adds one more term: skip the planes before, then the rows, then the columns.

    Colour to grayscale: who reads which bytes

    On a GPU all eight threads run at once; the animation goes one by one so the indices can be followed.

    The grayscale kernel

    #define CHANNELS 3                     // r, g, b: one byte each

__global__ void colorToGray(unsigned char* gray, const unsigned char* rgb,
                            int width, int height) {
  int col = blockIdx.x * blockDim.x + threadIdx.x;
  int row = blockIdx.y * blockDim.y + threadIdx.y;
  if (col < width && row < height) {
    int grayOffset = row * width + col;          // 1 byte per output pixel
    int rgbOffset  = grayOffset * CHANNELS;      // 3 bytes per input pixel
    unsigned char r = rgb[rgbOffset];
    unsigned char g = rgb[rgbOffset + 1];
    unsigned char b = rgb[rgbOffset + 2];
    gray[grayOffset] = (unsigned char)(0.299f * r + 0.587f * g + 0.114f * b);
  }
}
    • Lines 1–2 of the body: the thread’s column and row, as on slide 7; the guard lets only threads over a real pixel continue.
    • grayOffset: the output pixel, one byte each; rgbOffset: the same pixel in the input, three bytes each.
    • Each thread reads 3 bytes and writes 1. No thread touches another thread’s pixel: a pure map.
    • Weights: green counts most because the eye is most sensitive to it.

    Blur: every output pixel averages a patch

    3 × 3 patch, BLUR_SIZE = 1. Dashed cells are outside the picture and are skipped.

    The blur kernel

    #define BLUR_SIZE 1                    // patch radius: 1 gives 3x3, 3 gives 7x7

__global__ void blurKernel(const unsigned char* in, unsigned char* out, int w, int h) {
  int col = blockIdx.x * blockDim.x + threadIdx.x;
  int row = blockIdx.y * blockDim.y + threadIdx.y;
  if (col < w && row < h) {
    int sum = 0, pixels = 0;
    for (int dr = -BLUR_SIZE; dr <= BLUR_SIZE; ++dr)
      for (int dc = -BLUR_SIZE; dc <= BLUR_SIZE; ++dc) {
        int r = row + dr, c = col + dc;
        if (r >= 0 && r < h && c >= 0 && c < w) {   // skip pixels outside the image
          sum += in[r * w + c];
          ++pixels;                                  // corners: 4, edges: 6, inside: 9
        }
      }
    out[row * w + col] = (unsigned char)(sum / pixels);
  }
}
    • Same first lines and guard as grayscale: one thread per output pixel.
    • Two nested loops visit the patch, from -BLUR_SIZE to +BLUR_SIZE; the inner if skips neighbours outside the picture.
    • pixels counts how many were really added: 4 at a corner, 6 on an edge, 9 inside. Dividing by 9 everywhere would darken the borders.
    • Neighbouring threads read overlapping inputs; later chapters exploit that overlap.

    Matrix multiplication: one thread, one dot product

    Click any cell of P to follow that thread.

    Tiling P: each block owns a tile

    • 4 × 4 matrix, BLOCK_WIDTH = 2: four blocks, four threads each.
    • row = blockIdx.y * 2 + threadIdx.y, col = blockIdx.x * 2 + threadIdx.x.
    • Width 1000, blocks of 16 × 16: 63 × 63 = 3969 blocks, 1 016 064 threads, 1 000 000 of them compute an element.

    The matrix multiplication kernel and its host code

    __global__ void matMulKernel(const float* M, const float* N, float* P, int width) {
  int row = blockIdx.y * blockDim.y + threadIdx.y;
  int col = blockIdx.x * blockDim.x + threadIdx.x;
  if (row < width && col < width) {
    float sum = 0;
    for (int k = 0; k < width; ++k)
      sum += M[row * width + k] * N[k * width + col];   // row of M, column of N
    P[row * width + col] = sum;
  }
}
    void matMul(const float* M, const float* N, float* P, int width) {
  size_t bytes = (size_t)width * width * sizeof(float);
  float *M_d, *N_d, *P_d;
  cudaMalloc((void**)&M_d, bytes);
  cudaMalloc((void**)&N_d, bytes);
  cudaMalloc((void**)&P_d, bytes);
  cudaMemcpy(M_d, M, bytes, cudaMemcpyHostToDevice);
  cudaMemcpy(N_d, N, bytes, cudaMemcpyHostToDevice);

  dim3 block(16, 16);
  dim3 grid((width + 15) / 16, (width + 15) / 16);
  matMulKernel<<<grid, block>>>(M_d, N_d, P_d, width);

  cudaMemcpy(P, P_d, bytes, cudaMemcpyDeviceToHost);
  cudaFree(M_d); cudaFree(N_d); cudaFree(P_d);
}

    Walking through one thread

    Width 4, thread (0, 0) of block (0, 0): row 0, col 0.

    krow*W + kM elementk*W + colN element
    00M[0][0]0N[0][0]
    11M[0][1]4N[1][0]
    22M[0][2]8N[2][0]
    33M[0][3]12N[3][0]

    It writes P[0 * 4 + 0] = P[0][0].

    • Along a row of M the index grows by 1: consecutive memory.
    • Down a column of N it grows by width: one full row is skipped each step.
    • Thread (1, 0) of block (0, 0) has row 1: it reads M[4..7], the second row, and the same column of N.
    • The kernel has no outer loops over rows and columns: the grid is those loops.
    • Largest matrix one launch can cover is limited by grid and block sizes; past that, launch several grids or give each thread several elements.

    Solution 11.1 · a row or a column per thread
    // one thread computes one whole ROW of P
__global__ void matMulRowKernel(const float* M, const float* N,
                                float* P, int width) {
  int row = blockIdx.x * blockDim.x + threadIdx.x;
  if (row < width)
    for (int col = 0; col < width; ++col) {
      float sum = 0;
      for (int k = 0; k < width; ++k)
        sum += M[row * width + k] * N[k * width + col];
      P[row * width + col] = sum;
    }
}
    // one thread computes one whole COLUMN of P
__global__ void matMulColKernel(const float* M, const float* N,
                                float* P, int width) {
  int col = blockIdx.x * blockDim.x + threadIdx.x;
  if (col < width)
    for (int row = 0; row < width; ++row) {
      float sum = 0;
      for (int k = 0; k < width; ++k)
        sum += M[row * width + k] * N[k * width + col];
      P[row * width + col] = sum;
    }
}
    • Launch: one thread per row or per column, <<<(width + 255) / 256, 256>>>. For width 1000 that is 1000 threads, against 1 000 000 for one element per thread: too few to fill a GPU, each doing a million multiply-adds.
    • Row per thread: neighbouring threads read M[row*W+k] a whole row apart: scattered reads.
    • Column per thread: neighbouring threads read neighbouring N[k*W+col] and write neighbouring P: the friendlier pattern.

    Solution 11.2 · matrix-vector product
    // a[i] = dot(row i of B, c)
// B is N x N, row-major
__global__ void matVecKernel(float* a, const float* B,
                             const float* c, int N) {
  int i = blockIdx.x * blockDim.x + threadIdx.x;
  if (i < N) {
    float sum = 0;
    for (int j = 0; j < N; ++j)
      sum += B[i * N + j] * c[j];
    a[i] = sum;
  }
}
    void matVec(float* a, const float* B, const float* c, int N) {
  size_t vec = N * sizeof(float);
  size_t mat = (size_t)N * N * sizeof(float);
  float *a_d, *B_d, *c_d;
  cudaMalloc((void**)&a_d, vec);
  cudaMalloc((void**)&B_d, mat);
  cudaMalloc((void**)&c_d, vec);
  cudaMemcpy(B_d, B, mat, cudaMemcpyHostToDevice);
  cudaMemcpy(c_d, c, vec, cudaMemcpyHostToDevice);
  dim3 block(256);
  dim3 grid((N + 255) / 256);
  matVecKernel<<<grid, block>>>(a_d, B_d, c_d, N);
  cudaMemcpy(a, a_d, vec, cudaMemcpyDeviceToHost);
  cudaFree(a_d); cudaFree(B_d); cudaFree(c_d);
}
    • One thread per output element: thread i owns a[i] and walks row i of B, which starts at B[i * N].
    • Every thread reads all of c; B is read once in total. Host side: allocate, copy B and c over, launch, copy a back, free.

    Summary, and where this goes next

    • Grids and blocks have up to three dimensions; choose them to match the data.
    • Each thread turns blockIdx, blockDim and threadIdx into the position of its data, and checks that position exists.
    • Multidimensional data is stored flat, row after row; the kernel flattens indices itself.
    • Grayscale is a map; blur adds neighbours and borders; matrix multiplication gives each thread a dot product.
    • Next: how the GPU actually runs blocks, and why memory access patterns decide performance.
