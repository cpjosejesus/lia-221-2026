C++ concurrency · session 18

Parallel reduction

Many values in, one value out: a sum, a maximum, a count. The tree is easy; making it fast on a GPU is a tour of everything we know: control divergence, coalescing, shared memory, warp shuffles, atomics and thread coarsening. Seven kernels, each fixing one bottleneck of the previous one.

Based on chapter 10 of Programming Massively Parallel Processors (Hwu, Kirk, El Hajj). Runnable code for every kernel: ec2/reduction (laptop or Google Colab). Navigate with → ← or space; press p to print.

Reduction trees: max and sum

8 inputs, one operation per circle

Associativity, commutativity and floats

Associative (a ⊕ b) ⊕ c = a ⊕ (b ⊕ c): change the parentheses (the tree). Commutative a ⊕ b = b ⊕ a: also change the order of operands (the convergent kernel, atomics). Subtraction is neither (1 − 2 − 3 ≠ 1 − (2 − 3)); rewrite it as adding negatives. Fine print: int overflow is undefined behaviour in C++, so a reordering can overflow where the original did not; fmaxf with a NaN operand is not commutative; float + is not associative. If you can rule these out, treat the operator as associative and commutative.

Work, span and parallelism

N inputs
execution units0 = unlimited
  • Work: operations performed. Span: steps with unlimited resources.
  • Tree: N/2 + N/4 + … + 1 = N − 1 operations, as many as the loop: work-efficient.
  • But the parallelism collapses: 512 units in step 1, 1 in step 10. The average is far below the peak; on a GPU, the idle units of the late steps are the problem of this session.

Code: the simple kernel

__global__ void SimpleSumReductionKernel(float* input,
                                         float* output) {
  unsigned int i = 2*threadIdx.x;
  for (unsigned int stride = 1; stride <= blockDim.x;
       stride *= 2) {
    if (threadIdx.x % stride == 0) {
      input[i] += input[i + stride];
    }
    __syncthreads();
  }
  if (threadIdx.x == 0) {
    *output = input[0];
  }
}

// one block of N/2 threads: N ≤ 2048
SimpleSumReductionKernel<<<1, N/2>>>(input_d, output_d);
  • One block, so every thread can use __syncthreads(). Each thread adds two elements in the first step: N/2 threads.
  • Owner computes: thread t owns input[2t]; only it writes there.
  • The stride doubles: 1, 2, 4 … Active threads are the multiples of the stride.
  • __syncthreads() is a barrier and a memory fence for the block: writes before it are visible to every thread of the block after it.
  • The tree is computed in place: the input is destroyed.

Control divergence, step by step

16 elements, 8 threads, toy warps of 4 lanes

Code: the convergent kernel

__global__ void ConvergentSumReductionKernel(float* input,
                                             float* output) {
  unsigned int i = threadIdx.x;
  for (unsigned int stride = blockDim.x; stride >= 1;
       stride /= 2) {
    if (threadIdx.x < stride) {
      input[i] += input[i + stride];
    }
    __syncthreads();
  }
  if (threadIdx.x == 0) {
    *output = input[0];
  }
}
  • Three small changes: thread t owns input[t]; the stride starts at blockDim.x and halves; the active threads are those with t < stride.
  • Active threads stay consecutive, so whole warps switch off together: no divergence until fewer than 32 threads remain.
  • Pairs are now half a section apart: the operands are reordered, which needs commutativity as well as associativity.
  • Same number of additions, same result (up to float rounding), far fewer wasted lanes.

Execution resource efficiency

N elementspower of 2
  • N = 256: 128 threads, 4 warps, 8 iterations.
  • Simple: all 4 warps issue in the first 6 iterations (stride 1 … 32), then 2, then 1: (4·6 + 2 + 1)·32 = 864 lane slots for 255 adds: 255/864 = 0.30.
  • Convergent: 4, 2, 1 warps, then 5 iterations with 1 warp: (4 + 2 + 1 + 5·1)·32 = 384: 255/384 = 66 %.

Memory divergence: counting global requests

N = 256, 4 warps

Code: partial sums in shared memory

__global__ void SharedMemorySumReductionKernel(float* input,
                                               float* output) {
  __shared__ float input_s[BLOCK_DIM];
  unsigned int t = threadIdx.x;
  input_s[t] = input[t] + input[t + BLOCK_DIM];
  for (unsigned int stride = blockDim.x/2; stride >= 1;
       stride /= 2) {
    __syncthreads();
    if (threadIdx.x < stride) {
      input_s[t] += input_s[t + stride];
    }
  }
  if (threadIdx.x == 0) {
    *output = input_s[0];
  }
}
  • The convergent kernel writes every partial sum to global memory and reads it back. Keep them in shared memory instead.
  • The first add happens while loading, so the loop starts at blockDim.x/2. The barrier moves to the top of the loop.
  • BLOCK_DIM is a compile-time constant equal to blockDim.x: it sizes input_s and is the offset of the second element.
  • Global accesses: N + 1. Requests: N/32 + 1 = 8 + 1 = 9 for N = 256, against 36. And the input is not modified.

Global loads once, then shared memory

16 elements, BLOCK_DIM = 8

Warp-level primitives: __shfl_down_sync

#define WARP_SIZE 32
__device__ unsigned int warpIdx() { return threadIdx.x / WARP_SIZE; }
__device__ unsigned int laneIdx() { return threadIdx.x % WARP_SIZE; }

// T __shfl_down_sync(unsigned mask, T var,
//                    unsigned int delta, int width = 32);

__device__ __inline__ float warp_reduce(float val) {
  float partialSum = val;
  for (unsigned int stride = WARP_SIZE/2; stride > 0;
       stride /= 2) {
    partialSum += __shfl_down_sync(0xffffffff,
                                   partialSum, stride);
  }
  return partialSum;     // the total is valid in lane 0 only
}
  • __syncwarp(): a barrier for the 32 threads of one warp; diverged threads reconverge.
  • Shuffles read another lane's register: no shared memory, no __syncthreads().
  • mask: lanes taking part (all 32 here). var: the value each sender offers. delta: lane i receives lane i + delta's var; if i + delta falls outside the group, its own.
  • Thread 33: warpIdx 1, laneIdx 1.

Shuffles: values move between registers

Code: the warp-level kernel

__global__ void WarpLevelSumReductionKernel(float* input,
                                            float* output) {
  __shared__ float input_s[BLOCK_DIM];
  unsigned int t = threadIdx.x;
  input_s[t] = input[t] + input[t + BLOCK_DIM];
  for (unsigned int stride = blockDim.x/2;
       stride >= WARP_SIZE; stride /= 2) {
    __syncthreads();
    if (threadIdx.x < stride) {
      input_s[t] += input_s[t + stride];
    }
  }
  __syncthreads();
  if (warpIdx() == 0) {
    float partialSum = input_s[t];
    partialSum = warp_reduce(partialSum);
    if (threadIdx.x == 0) {
      *output = partialSum;
    }
  }
}
  • From stride 32 down, only warp 0 works in the shared-memory kernel, yet every step pays a block-wide barrier and shared-memory round trips.
  • Here the shared loop stops after stride 32: input_s[0 … 31] holds 32 partial sums.
  • One last barrier, then warp 0 loads them into registers and finishes with 5 shuffles.
  • Strides 16 … 1 lose their barriers and shared accesses.

All take a mask of participating lanes. Shuffles take an optional width (a power of 2 up to 32): width = 8 makes a warp behave as four independent groups of eight. Since Volta, lanes of a warp may run independently, which is why the _sync versions with a mask are required.

Code: two-stage warp-wide reduction

__global__ void TwoStageWarpLevelSumReductionKernel(
    float* input, float* output) {
  unsigned int t = threadIdx.x;
  float partialSum = input[t] + input[t + BLOCK_DIM];
  partialSum = warp_reduce(partialSum);    // stage 1

  __shared__ float partialSums_s[BLOCK_DIM/WARP_SIZE];
  if (laneIdx() == 0) {
    partialSums_s[warpIdx()] = partialSum;
  }
  __syncthreads();                       // the only barrier

  if (warpIdx() == 0) {
    float partialSum = partialSums_s[t];
    partialSum = warp_reduce(partialSum);  // stage 2
    if (threadIdx.x == 0) {
      *output = partialSum;
    }
  }
}
  • Stage 1: every warp reduces its own 64 elements in registers. Lane 0 puts the warp's sum in shared memory.
  • One barrier, then warp 0 reduces the per-warp sums. At most 1024 threads = 32 warps, so one warp is enough.
  • The listing assumes BLOCK_DIM = 1024. With fewer threads, guard the load: t < BLOCK_DIM/WARP_SIZE ? partialSums_s[t] : 0.0f.

One stage or two? Barriers versus divergence

BLOCK_DIMpower of 2
  • Two-stage: all warps stay busy in stage 1, but inside each warp only 16, 8, 4, 2, 1 lanes do useful work per shuffle: more divergence.
  • In exchange: one barrier and almost no shared memory.
  • Once the data is loaded, a reduction is latency-bound: few instructions, each waiting on the previous one. Removing barriers and shared-memory round trips shortens the critical path; removing idle lanes would only free cycles that the warps spend stalled anyway.

Arbitrary length: one segment per block

4 blocks, 8 elements each

Code: multi-block reduction with atomic_ref

__global__ void reduce_kernel(float* input, float* output,
                              unsigned int N) {
  unsigned int segment = 2*blockDim.x*blockIdx.x;
  unsigned int i = segment + threadIdx.x;
  float partialSum = input[i] + input[i + BLOCK_DIM];
  partialSum = warp_reduce(partialSum);

  __shared__ float partialSums_s[BLOCK_DIM/WARP_SIZE];
  if (threadIdx.x%WARP_SIZE == 0) {
    partialSums_s[threadIdx.x/WARP_SIZE] = partialSum;
  }
  __syncthreads();

  if (threadIdx.x < WARP_SIZE) {
    float partialSum = partialSums_s[threadIdx.x];
    partialSum = warp_reduce(partialSum);
    if (threadIdx.x == 0) {
      cuda::atomic_ref<float, cuda::thread_scope_device>
          output_ref(*output);
      output_ref.fetch_add(partialSum,
                           cuda::memory_order_relaxed);
    }
  }
}
// host: *output = 0; N / (2*BLOCK_DIM) blocks of BLOCK_DIM
  • Block b reduces the segment starting at 2·blockDim.x·b; i replaces t for global indices.
  • The leader thread adds the block's sum with a device-scope fetch_add (session 17).
  • N is not used yet: N must be a multiple of 2·BLOCK_DIM (exercise 18.5).
  • Alternatives: write partial[blockIdx.x], then a second one-block kernel or the host: fixed order, no atomics.

Thread coarsening: serialize the blocks yourself

Toy model: one block per SM at a time; a step is one round of adds by a whole block. Each thread first adds 2 × COARSE_FACTOR elements (2C − 1 steps, all threads busy), then the tree takes log₂ T steps.

Code: the coarsened kernel

__global__ void CoarsenedSumReductionKernel(float* input,
                                            float* output) {
  unsigned int segment = COARSE_FACTOR*2*blockDim.x*blockIdx.x;
  unsigned int i = segment + threadIdx.x;
  float partialSum = input[i];
  for (unsigned int c = 1; c < COARSE_FACTOR*2; ++c) {
    partialSum += input[i + c*BLOCK_DIM];
  }
  // from here on as in the two-stage, multi-block kernel
  partialSum = warp_reduce(partialSum);
  __shared__ float partialSums_s[BLOCK_DIM/WARP_SIZE];
  if (laneIdx() == 0) {
    partialSums_s[warpIdx()] = partialSum;
  }
  __syncthreads();
  if (warpIdx() == 0) {
    float partialSum = partialSums_s[threadIdx.x];
    partialSum = warp_reduce(partialSum);
    if (threadIdx.x == 0) {
      cuda::atomic_ref<float, cuda::thread_scope_device>
          output_ref(*output);
      output_ref.fetch_add(partialSum,
                           cuda::memory_order_relaxed);
    }
  }
}
  • Segments are COARSE_FACTOR times longer; each thread adds 2 × COARSE_FACTOR elements, BLOCK_DIM apart: coalesced, no barriers.
  • The book shows only this head and writes ... for the rest; the rest is the two-stage block reduction plus the atomic.
  • Grid: N / (COARSE_FACTOR · 2 · BLOCK_DIM) blocks.
  • Pick the largest factor that still leaves enough blocks to fill every SM.

Summary

  • A reduction derives one value from many with an operator and its identity. The tree does N − 1 operations, like the loop, in log₂ N steps, if the operator is associative (and commutative once operands are reordered). Floats only approximately qualify.
  • The simple kernel uses 30 % of the lanes it occupies for N = 256: active threads drift apart (control divergence) and their accesses are strided (memory divergence, 141 requests). Keeping active threads consecutive gives 66 % and 36 requests.
  • Shared memory cuts global traffic to N + 1 accesses (9 requests). Warp shuffles remove barriers and shared accesses, in the last steps or, with two stages, everywhere.
  • Blocks cannot synchronize: each reduces a segment and adds its result with an atomic (or writes a partial sum for a second pass). Coarsening serializes the work ourselves, so fewer steps run with idle threads.
  • In practice call Thrust or CUB; the techniques reappear in scan (next session), histograms and sorting.

Solutions 18.4 and 18.5

// 18.4: maximum; host sets *output = -INFINITY
__device__ float warp_max(float v) {
  for (unsigned int s = WARP_SIZE/2; s > 0; s /= 2)
    v = fmaxf(v, __shfl_down_sync(0xffffffff, v, s));
  return v;
}
__global__ void CoarsenedMaxReductionKernel(
    float* input, float* output) {
  unsigned int i = COARSE_FACTOR*2*blockDim.x*blockIdx.x
                   + threadIdx.x;
  float m = input[i];
  for (unsigned int c = 1; c < COARSE_FACTOR*2; ++c)
    m = fmaxf(m, input[i + c*BLOCK_DIM]);
  m = warp_max(m);
  __shared__ float m_s[BLOCK_DIM/WARP_SIZE];
  if (laneIdx() == 0) m_s[warpIdx()] = m;
  __syncthreads();
  if (warpIdx() == 0) {
    m = warp_max(threadIdx.x < BLOCK_DIM/WARP_SIZE
                 ? m_s[threadIdx.x] : -INFINITY);
    if (threadIdx.x == 0) {
      cuda::atomic_ref<float, cuda::thread_scope_device>
          out(*output);
      float old = out.load(cuda::memory_order_relaxed);
      while (old < m && !out.compare_exchange_strong(
                 old, m, cuda::memory_order_relaxed)) {}
    }
  }
}

      partialSum += input[i + c*BLOCK_DIM];

  }

}
